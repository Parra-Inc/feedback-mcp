# PH follow-up (T+1 day)

## Capture

- **Rank + numbers:** final rank/badge for the day, upvotes, comments, and (against the
  real goal) GitHub stars and repo traffic driven from PH.
- **What people asked for:** file each recurring request as a GitHub issue. The "I wish it
  had a dashboard" replies are especially worth logging, even though the answer is "by
  design," because volume tells you whether an optional read-only UI is worth it.
- **New makers/users:** note anyone who said they'd self-host or contribute.

## Thank

- Reply to every remaining comment. Thank your hunter (if you used one) and the most
  engaged commenters publicly.
- Answer the "what would you want your AI to tell you every morning?" question-thread
  yourself with your favorite reply, which keeps the thread alive into day 2.

## Feed the next thing

- A **launch recap** on X / your own channels: "We launched Feedback MCP on HN and PH:
  here's what people actually asked." Combines both launches into durable content.
- The best feature request becomes the next changelog entry, and the changelog feeds the
  `release` skill for the next announcement.

## The arc

HN (Day 1) → Product Hunt (Day 4) → recap (Day 6). After that, the durable channel for a
tool like this is SEO + the GitHub README + word of mouth, not more launches. Save the
next launch moment for a real milestone (Mongo support, the feedback widget, or a "1.0").
